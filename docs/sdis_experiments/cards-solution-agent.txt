THE PROBLEM TO SOLVE
Find the repeating parts of a portal page (cards / tiles, list rows, table rows, field rows inside a card) from a raw UIA read, and compare two clients' pages of the same link so that every datapoint is paired with the SAME field on the other client's page. Open bugs your design must answer (numbers from progress.md section 4):
- 7, 8: Firefox drops a card's wrapper (its parts become loose siblings) or adds an inner Group; the tree method misses those cards.
- 9: unrelated single-text boxes grouped by type likeness.
- 10: field rows inside a card are paired with the wrong card's field rows (inner groups matched independently of their parent's pairing), and each value is reported twice.
- 11: label vs value is guessed from shape (variable_alignment); a value should be known by its label.
- 12: the same page from Chrome and Firefox has differently shaped trees.
- 13: ρ (name recurrence cut-off) cannot be chosen; r depends on how many cards each capture has.
The owner's idea to evaluate (experiment 3, "arrangement" / "packing pattern"): start from the leaf elements and their screen boxes; find arrangements of neighbouring elements (relative position of one element to the next, by element kind) that REPEAT within one page; each set of elements held together by a repeating arrangement is one card or row, nesting falls out (small patterns inside big ones); then compare two clients top-down by arrangement (directions and order, not pixels, across clients): cards paired by their name text, fields by their place in the matched card. Known limit: the arrangement cannot tell two cards with identical layouts apart (IFF vs GSTR-1); identity still needs the name text.
